# 监控告警配置（建议稿）

本配置以应用自身提供的接口为基础，支持 Prometheus/Grafana 或最简 Cron+curl 方案。

## 1. 监控数据源

- 状态：`GET /api/status`
  - 关注字段：`update`、`preprocess`、`pkl`、`pkl_ready`
- 指标：`GET /api/metrics`
  - 关注字段：缓存命中、耗时统计、429/忙碌等

## 2. 告警规则（推荐）

- A1：接口错误率升高
  - 触发：近 5 分钟错误率 > 1%
  - 处置：回滚最近一次变更或降级（关闭自定义因子/降低并发）
- A2：RT 升高
  - 触发：p95 RT 较基线升高 ≥20% 持续 10 分钟
  - 处置：检查是否落到 CSV 路径、缓存是否失效、是否存在更新锁争用
- A3：更新卡住
  - 触发：`update.running==true` 持续 > 10 分钟
  - 处置：查 `.pipeline.lock` 与日志，必要时重启更新线程
- A4：预处理卡住
  - 触发：`preprocess.running==true` 持续 > 15 分钟 或 `preprocess.last_error!=null`
  - 处置：检查预处理输入目录、磁盘 IO、Parquet 引擎可用性
- A5：PKL 构建失败或过慢
  - 触发：`pkl.last_error!=null` 或 `pkl.running==true` 持续 > 20 分钟
  - 处置：回退到 CSV/预处理读取，降低 workers，检查磁盘与 CPU
- A6：企业微信推送异常
  - 触发：每小时 push 结果持续“无命中”且策略配置非空
  - 处置：检查筛选配置与 `series` 补齐状态（可通过日志与 `/api/status`）

## 3. 最简 Cron+curl 方案（无 Prometheus）

Linux Crontab 每分钟检查一次状态，发现异常立即推送到企业微信机器人：

```bash
*/1 * * * * curl -fsS http://127.0.0.1:8001/api/status | python -c 'import json,sys; j=json.load(sys.stdin); import os; u=j.get(\"update\") or {}; p=j.get(\"preprocess\") or {}; k=j.get(\"pkl\") or {}; ok=(u.get(\"last_error\") is None and p.get(\"last_error\") is None and k.get(\"last_error\") is None); sys.exit(0 if ok else 1)'
```

若需要推送，可把上述检查包装为脚本，并在失败时调用现有企业微信 webhook 发送逻辑（参考 [wecom_sender.py](file:///d:/量化交易/中性1.8/apps/crypto_screener/app/wecom_sender.py)）。

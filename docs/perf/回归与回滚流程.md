# 性能回归与回滚流程（Route1）

目标：每次变更只解决单点；变更后在同压测模型下回归验证，未达标立即回滚并记录复盘。

## 1. 基线准备

- 启动服务（本地压测可用匿名模式）：

```powershell
$env:QC_DISABLE_AUTH='1'
$env:QC_SCREENER_HOST='127.0.0.1'
$env:QC_SCREENER_PORT='8001'
C:/anaconda3/envs/Gamma/python.exe apps/crypto_screener/app/web_server.py
```

- 生成基线：

```powershell
C:/anaconda3/envs/Gamma/python.exe tools/perf/bench_http.py --endpoint latest_enriched --vus 1,10,50 --requests-per-user 3 --out tools/perf/baseline_latest_enriched.json
C:/anaconda3/envs/Gamma/python.exe tools/perf/bench_http.py --endpoint kline --vus 1,10,50 --requests-per-user 5 --timeout-s 10 --kline-market swap --kline-symbol BTC-USDT --kline-tail 720 --out tools/perf/baseline_kline.json
```

## 2. 单点变更的推荐流程

- 每个优化点独立一个提交（便于回滚）：

```powershell
git add <改动文件...>
git commit -m "perf(route1): <优化点简述>"
```

- 变更后回归压测：

```powershell
C:/anaconda3/envs/Gamma/python.exe tools/perf/bench_http.py --endpoint latest_enriched --vus 1,10,50 --requests-per-user 3 --out tools/perf/candidate_latest_enriched.json
C:/anaconda3/envs/Gamma/python.exe tools/perf/regression_check.py --baseline tools/perf/baseline_latest_enriched.json --candidate tools/perf/candidate_latest_enriched.json --users 50
```

判定规则：
- p95 RT 下降 ≥10% 或 QPS 提升 ≥10% 或 错误率下降 ≥10%
- 错误率不得上升
- CPU、内存不得明显恶化（默认容忍 20%）

## 3. 立即回滚

- 若尚未提交：

```powershell
git restore <改动文件...>
```

- 若已提交：

```powershell
git revert <commit_sha>
```

## 4. 复盘落盘

每次失败回滚需要追加记录：
- 变更点、预期假设
- 压测对比（baseline vs candidate）
- 不达标原因定位（CPU/IO/锁/缓存命中/数据规模等）
- 下一轮改动计划
